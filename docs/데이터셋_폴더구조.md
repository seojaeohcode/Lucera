# 회의록 원문 데이터셋 폴더 구조

현재 프로젝트는 회의록 파일의 생애주기와 DB를 분리해 관리한다. 같은 문서의 원본, 변환본, OCR/구조화 결과를 덮어쓰지 않고 `document_artifact.parent_artifact_id`와 SHA-256으로 연결한다.

```text
data/
├─ db/
│  ├─ lucera_minutes.sqlite3       # 현재 운영 DB
│  ├─ backups/                     # 복구용 백업
│  └─ snapshots/                   # 과거 구축본·분석본
├─ dataset/minutes/
│  ├─ original/
│  │  ├─ api_json/                 # API 상세 원문 JSON
│  │  ├─ api_listings/             # 수집 당시 목록 응답
│  │  ├─ html/                     # 포털 HTML snapshot
│  │  ├─ hwp/region_<code>/        # 공식 HWP/HWPX 원문
│  │  └─ pdf/                      # 공식 PDF 원문
│  ├─ normalized/
│  │  ├─ pdf_from_hwp/             # HWP/HWPX 변환 PDF
│  │  └─ pdf_from_html/            # HTML fallback 인쇄 PDF
│  ├─ extracted/
│  │  ├─ opendataloader/           # OpenDataLoader JSON/text
│  │  └─ opendataloader_experiment/# 실험용 추출 결과
│  ├─ rejected/                    # PDF로 확정할 수 없어 제외한 입력
│  ├─ manifests/                   # 수집·변환 manifest
│  ├─ reports/                     # 구축·검증·지역별 보고서
│  └─ qa/                          # 렌더링 등 시각 검증 자료
└─ reference/
   ├─ gazetteer/                   # 광주·전남 행정구역/지명 사전
   ├─ public_api/                  # 태양광·계통 공공 API 원자료
   └─ source_materials/            # 원자료 CSV 등 참고자료
```

## 재구축 순서

```powershell
$py = 'C:\Python313\python.exe'
& $py scripts\convert_hwp.py
& $py scripts\html_to_pdf.py
& $py scripts\build_browser_db.py
& $py scripts\validate_browser_db.py
```

경로 변경이나 파일 재배치가 필요한 경우에는 `scripts/reorganize_workspace.py`를 사용한다. 기본 실행은 dry-run이며, 실제 변경은 `--apply`를 명시해야 한다. 이 스크립트는 활성 DB 백업을 먼저 만들고, artifact의 `storage_uri`를 새 경로로 갱신한다.

DB의 기준 조회 계층은 다음과 같다.

```text
source_document → meeting → document_page → meeting_segment
                                            └→ episode → conflict_case
                                                        └→ case_evidence → meeting_segment
```

따라서 문서 하나에서 여러 민원을 분리해 조회할 수 있고, 각 민원은 여러 원문 문단을 순서대로 반환한다. 지역·주소·좌표가 불확실한 경우에도 원문 근거와 위치 후보를 별도 보존한다.
